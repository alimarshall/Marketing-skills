# Ad Library & Review

Keep concepts, copy, visuals, evidence and review status aligned as the library grows. Use an existing review surface when it works; a gallery is not always necessary for a small copy task.

## Establish the source of truth

Inspect the current library and its generation process before editing. Assign or preserve stable concept IDs. Distinguish a concept from headline, visual, placement and version variants. Retain the buyer, use case, angle, source evidence, claims, copy, assets and status needed to understand each concept. Reuse the existing schema rather than introducing a second competing tracker.

Maintain explicit statuses such as draft, needs evidence, ready for review, accepted or retired. User approval of a creative is separate from authorization to publish. Keep historical versions recoverable and out of the default current view unless requested.

## Apply feedback coherently

Map feedback to concept IDs and the affected components: image, headline, subheader, caption, UI sequence, typography or all uses of an asset. Resolve references by title and current version; clarify only when ambiguity would change the edit materially. Preserve accepted work that was not implicated.

For shared asset feedback, find every active use. Update the underlying source, regenerate affected exports and synchronize the gallery and copy record. Do not only edit the visible preview while leaving the downloadable asset stale. Retire rejected imagery from active variants without deleting unrelated originals or historical evidence.

When asked to see several rounds in one tab, provide one review view with clear version labels and a sensible default. Do not silently replace a requested historical comparison with only the latest batch.

## Build or update review output

Use the existing project format. For a local gallery, use relative asset links where appropriate, readable thumbnails, full-size access and filters that match the actual library. Do not add publishing, account management or analytics without a request. If a new hosted website is requested, follow the relevant site tool workflow rather than assuming a local gallery is published.

For structured assets, make the manifest the source for counts, titles and links when practical. Keep private research and internal claim notes separate from public-ready exports.

## Verify the delivered set

Check that intended current concepts appear exactly once per requested variant, images load, exports correspond to their labels, copy matches the current source and retired assets are absent from active views. Visually inspect changed layouts at their placement size and mobile reading size. Spot-check unchanged groups rather than rerendering the entire history without a reason.

Report actual concept and export counts only from the files or manifest. Distinguish produced, reviewed and accepted states. Deliver the review entry point and useful downloadable assets; do not claim the user has seen or approved them.

Work with `ad-creative-direction`, `product-ui-storytelling` and the research/proof skills as needed. `ads-workflow` can coordinate a broader project if installed; none of these skills grants publication permission.
